# サッカークラブ経営ゲーム

PCのブラウザで遊ぶ、リアル志向のサッカークラブ経営シミュレーション。
日本風の架空の国の1部リーグ（18クラブ）で、監督とGMを兼ねてシーズンを戦う。

今は **フェーズ1** まで。クラブを選んで、スタメンと戦術を決め、試合を観戦しながら采配し、34節を戦って優勝が決まるまで遊べる。

## 必要なもの

- Node.js 22 以上

## 遊び方

最初に一度だけ、必要な道具を入れる。

```sh
npm install
```

ブラウザで遊ぶ：

```sh
npm run dev
```

表示された `http://localhost:5173/` をブラウザで開く。

1. 「新しいゲーム」で監督の名前を入れ、就任するクラブを選ぶ
2. 「戦術」でフォーメーション、先発と控え、役割、チーム指示を決める
3. 右上の「次の試合へ」→「試合開始」で観戦する
   - 速さ（等倍・2倍・4倍）を変えたり、一時停止して交代や戦術の変更ができる
   - 「結果まで飛ばす」と、残りの交代と戦術の変更はAIに任せて最後まで進む
4. 試合後のレポートを見て「結果を確定して次へ」。34節を終えると優勝が決まる

セーブはブラウザの中に自動で保存される（試合の結果を確定したときと、メンバーや戦術を変えたとき）。
タイトル画面の「書き出す」でファイルに保存し、「ファイルから読み込む」で戻せる。
試合の途中でブラウザを閉じると、その試合は確定前の状態（試合開始前）に戻る。

## ルール（`src/game/rules.ts`）

- 勝ち3・引き分け1・負け0。順位は勝ち点 → 得失点差 → 総得点 → 直接対決
- 試合のメンバーは先発11人と控え9人。外国籍選手はメンバーに5人まで
- 交代は5人まで、交代できる回数は3回まで（ハーフタイムは数えない）
- 警告4枚で1試合、2枚目の警告での退場は1試合、一発退場は2試合の出場停止
- 他クラブの選手の能力は「12〜16」のような幅で表示される（スカウトはフェーズ4）

## 開発用のコマンド

```sh
npm test            # 自動テスト（約1分）
npm run typecheck   # 型のチェック
npm run build       # 公開用のファイルを dist/ に作る
npm run match       # ターミナルで1試合を動かす（--seed=42、--all、--home-pressing=2 など）
npm run simulate    # たくさん試合を回して、結果の分布を要件定義書の目標と比べる
```

`dist/` の中身は静的なファイルなので、GitHub Pages などにそのまま置いて公開できる。

## フォルダの構成

| 場所 | 中身 |
| --- | --- |
| `src/engine/` | 試合エンジン。`match.ts`（ゾーン方式、交代、試合中の采配）、`roles.ts`（役割）、`ratings.ts`（ポジションごとの総合力）、`config.ts`（調整用の数値） |
| `src/game/` | リーグとシーズンの仕組み。`world.ts`（世界の自動生成）、`schedule.ts`（日程）、`standings.ts`（順位表）、`selection.ts`（メンバー選び）、`season.ts`（節の進行）、`save.ts`（セーブデータ） |
| `src/ui/` | 画面（React）。`screens/` が各画面、`components/` が部品、`store.ts` が画面全体の状態、`storage.ts` がブラウザへの保存、`sim.worker.ts` が他会場の試合を計算する Web Worker |
| `src/data/` | 選手の自動生成と名前の材料 |
| `src/cli/` | ターミナルで動かすためのコマンド |
| `test/` | 自動テスト |

## 試合エンジンのしくみ（要点）

- ピッチを縦6×横5の30マスに分け、ボールを持った選手のプレー（パス、ドリブル、シュート、クロス、クリア）を一手ずつ計算する
- 各選手は、フォーメーション、役割、チーム指示から「攻撃時の位置」と「守備時の位置」を持ち、近くのマスに影響を与える
- プレーの成功率は、攻める側の能力と、そのマスで守る側がかけている「圧力」で決まる
- プレスは「相手陣内でボールに寄せる力」として圧力に加わる。前線と中盤の運動量・スピードが高いほど強い
- スタミナは時間とともに減り、能力値が下がる。プレスやテンポを上げると早く減る
- AIの監督は、60・70・80分に疲れた選手を交代し、負けていれば攻撃的に、勝っていれば守備的に切り替える
- 試合の計算では、能力値の平均（12）からの差を0.85倍に縮めて使い、番狂わせが起きる余地を残している

結果の分布を変えたいときは、まず `src/engine/config.ts` の数値を変えて、`npm run simulate` で確かめる。
