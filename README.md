# イレブン・アーキテクト（XI ARCHITECT）

PCのブラウザで遊ぶ、リアル志向のサッカークラブ経営シミュレーション。
日本風の架空の国の1部リーグ（18クラブ）で、監督とGMを兼ねてシーズンを戦う。

**ブラウザで遊ぶ：https://enbi0001713000.github.io/eleven-architect/** （インストール不要。PCの Chrome、Edge、Firefox、Safari の新しい版）

- セーブはそのブラウザの中にだけ残る。ブラウザのデータを消すと消えるので、ときどきタイトル画面の「書き出す」でファイルに残す。別のPCで続けるときも、書き出したファイルを読み込む
- 舞台は架空の国。クラブ、選手、人物は実在のものとは関係ない
- 不具合や要望は [Issues](https://github.com/enbi0001713000/eleven-architect/issues) へ

版は **1.0.0**（フェーズ4まで：契約、移籍、スカウトと新人）。クラブを選んで、練習と戦術を決め、1日ずつ時間を進めながら、試合を観戦して采配し、選手と面談し、何シーズンでも続けて遊べる。
選手はコンディション、疲労、モラル、ケガを持ち、練習と出場で成長し、年を取ると衰えて引退する。
フェーズ2.5では試合エンジンを見直し、戦術の組み合わせで結果が変わるようにした（ハイラインの裏、ボールを失った直後、長いボール、SBの役割）。
フェーズ3-Aでクラブのお金が加わった。入場料、スポンサー、グッズ、リーグからの配分、賞金が入り、年俸と運営費が出ていく。オーナーが決める予算の中で年俸を払い、チケットの値段とスポンサーを決め、足りなければ借り入れをする。貯めた黒字は、オーナーに頼んで予算に回せる。
フェーズ3-Bでオーナーの評価が加わった。シーズン前にオーナーが順位と財務の目標を示し（開幕までに1回だけ話し合える）、成績とお金の状況で信頼度が上下する。信頼度が下がると警告が届き、下がりすぎると解任される。
オーナー、営業担当、選手、記者とのやり取りは会話画面で行う。大事な出来事が起きると、会話画面が開く（設定で切れる）。
フェーズ3-Cで監督のキャリアが加わった。新しいゲームで監督の経歴（評判と小さな得意が変わる）と難易度を選び、成績で監督の評判が上下する。評判が上がると格上のクラブからオファーが届き、解任されても無職のまま日を進めて、オファーや応募で別のクラブの監督に戻れる。AIクラブの監督も、成績が悪いと解任される。
フェーズ4-Aで選手の契約が加わった。今年で契約が切れる選手とは7月から11月まで更新の交渉をし（相手は代理人。年俸、年数、約束する役割、違約金、出来高ボーナスを決める）、12月からは他クラブの契約満了の選手と仮の契約ができる。選手には市場価値が付き、AIクラブも契約満了の選手を獲る。
フェーズ4-Bで移籍が加わった。冬（1月5日〜3月27日）と夏（7月15日〜8月15日）の移籍期間に、他クラブの選手に移籍金かレンタルを申し込み、クラブと合意したら代理人と契約を結ぶ。違約金を払えば、クラブは断れない。自分の選手にも他クラブや海外のクラブから申し込みが届き、受ける・断る・額を返すを選ぶ。AIクラブ同士も、クラブの規模に合った方針で選手を売り買いし、若手を貸し借りする。
フェーズ4-Cでスカウトと新人が加わった。スカウトを送って選手を調べると、能力の幅が狭まり、伸びしろや人柄、勧める度合いが分かる。地域とポジションを決めて探しに行けば、海外の選手も見つかり、獲得を申し込める。毎年6月には高校生・大学生の新人の候補が発表され、内定を出せる（他クラブと競争になる）。
フェーズ3.5で遊びやすくした。役割にアンカー、ボランチ、トップ下、シャドー、ストライカーなどの呼び方を付け、役割とフォーメーション（4-1-4-1、3-4-2-1、3-5-2）を増やした。画面は明るい配色を初期にし、暗い配色も選べる。ゲーム開始時や、画面・機能を初めて使うときは、アシスタントコーチがチュートリアルで案内する。ファンクラブができ、年会費の収入が入る。

## 必要なもの

- Node.js 22 以上

## 手元で動かす

最初に一度だけ、必要な道具を入れる。

```sh
npm install
```

ブラウザで遊ぶ：

```sh
npm run dev
```

表示された `http://localhost:5173/` をブラウザで開く。

## 遊び方

1. 「新しいゲーム」で監督の名前を入れ、就任するクラブを選ぶ（開幕の1週間前から始まる）
2. 「練習」で方針と強度、「戦術」でフォーメーション、先発と控え、役割、チーム指示を決める
3. 右上の「次の出来事まで進める」で時間を進める。試合の日と、大事な知らせ（ケガ、選手からの申し出など）が届いた日に止まる。「＋1日」で1日ずつも進められる
4. 試合の日は「試合へ」→（記者会見）→「試合開始」→ 試合前の声かけ → 観戦
   - 速さ（等倍・2倍・4倍）を変えたり、一時停止して交代や戦術の変更ができる
   - ハーフタイムと試合後にも声かけができる
   - 「結果まで飛ばす」と、残りの交代と戦術の変更はAIに任せて最後まで進む
5. 試合後のレポートを見て「結果を確定して次へ」。34節を終えると優勝が決まる
6. そのまま進めると、12月にシーズンの総括、引退の発表、契約の更新、1月に新しい日程と新人の加入があり、2月末に次のシーズンが始まる

セーブはブラウザの中に自動で保存される（時間を進めたとき、試合の結果を確定したとき、メンバーや戦術を変えたとき）。
古い版（フェーズ1〜3-A）のセーブデータは、読み込むと自動で今の形に直される。フェーズ2のセーブデータは、年俸を新しい水準で計算し直し、お金の記録は読み込んだ日から始まる。フェーズ3-Aまでのセーブデータでは、オーナーの信頼度は60から始まる。
タイトル画面の「書き出す」でファイルに保存し、「ファイルから読み込む」で戻せる。
試合の途中でブラウザを閉じると、その試合は確定前の状態（試合開始前）に戻る。

## ルール（`src/game/rules.ts`）

- 勝ち3・引き分け1・負け0。順位は勝ち点 → 得失点差 → 総得点 → 直接対決
- 試合のメンバーは先発11人と控え9人。外国籍選手はメンバーに5人まで
- 交代は5人まで、交代できる回数は3回まで（ハーフタイムは数えない）
- 警告4枚で1試合、2枚目の警告での退場は1試合、一発退場は2試合の出場停止
- 他クラブの選手の能力は「12〜16」のような幅で表示される。幅は知識度で決まり、スカウトで調べると狭まる
- ケガの残りが3日以内の選手は、完治前でも試合に出せる（再発しやすい）

## 進行のしくみ（フェーズ2、数値は `src/game/balance.ts`）

- コンディション：短期の体力。試合で減り、数日で戻る。悪いと、試合開始時のスタミナが下がる（70%なら88から始まる）
- 蓄積疲労：試合と練習の負荷がたまる長期の疲れ。高いと能力が下がり、ケガをしやすい。過密日程とハードな練習で増える
- ケガ：打撲、捻挫、肉離れ、腰痛、骨折、靭帯損傷、前十字靭帯断裂。種類ごとに離脱日数の幅がある。復帰してしばらくは同じ部位を痛めやすい
- 戦術の熟成度：フォーメーションとチーム指示ごとに0〜100%。低いと判断力、ポジショニング、オフ・ザ・ボールが下がる。新しく入った選手は戦術に慣れていない
- 成長と衰え：毎週、練習・出場・年齢・潜在能力・プロ意識で少しずつ変わる。30歳を過ぎるとフィジカルから衰える
- モラル：試合結果、自分の出来、出場機会（契約で約束した役割と比べる）、面談、声かけ、記者会見で変わり、試合での出来に響く
- シーズンの切り替え：12月1日に契約の締め切り（下の「契約」）、12月20日に引退の発表、1月1日に契約満了の選手が移り、1月10日に新人が加入する（内定を受けた候補と、強化部が獲る新人。1クラブ2〜3人が目安）

## お金のしくみ（フェーズ3-A、数値は `src/game/financeBalance.ts`）

- 年度は1月〜12月。毎月1日に前の月を締め、1月1日に前の年度を締めて、オーナーが新しい年の予算を決める
- 入場料：観客数 × 席の種類（ゴール裏、バックスタンド、メインスタンド、VIP）ごとの値段。観客はファンの数、最近の成績、相手（強いクラブ、ダービー）、平日かどうか、ファンの雰囲気、値段で決まり、収容人数を超えない
- スポンサー：ユニフォームの胸、背中、袖、パンツ、スタジアムの命名権、オフィシャルパートナーの6つの枠に、1社ずつ契約する。合計の年額は評判と地元企業の力で決まる。契約が今年で切れる枠には、12月1日に営業担当から提案が3つずつ届く（長期、標準、1年の高額、成績連動）。選ばなければ標準の契約になる
- グッズ：ファンの数と試合の日の観客、人気選手（総合力15以上）の数で増える。売上の半分は仕入れ
- リーグからの配分：全クラブ均等の分と、前年の順位に応じた分（1クラブ1.2億〜9億円）。賞金は優勝3億、2位1.2億、3位6,000万円
- 支出：選手の年俸、クラブの運営費（スタッフ、育成、遠征、事務など）、試合の運営費、グッズの仕入れ、借り入れの利息
- 予算：見込みの収支の余りと、手元のお金の余裕の一部から、オーナーが総予算を決める。年俸予算と移籍予算の配分は変えられる。手元のお金に余裕があれば、オーナーに頼んで、その半分まで予算に足してもらえる（貯めた黒字で、他クラブの主力に高い年俸や移籍金を出せる）。選手を売ると、移籍金の半分がその年の移籍予算に足される。年俸予算は、今の年俸の合計と前の年に払った年俸の大きいほうの1.05倍。強化部に任せた更新とAIクラブの更新では、年俸の合計が年俸予算を超えると、年俸を相場より最大2割下げる
- 借り入れ：上限は規模で決まり（大30億、中15億、小7億円）、毎月元金と利息を返す。手元のお金がマイナスになると、自動で緊急の借り入れをし、それでも足りなければオーナーが入れる（破産はしない）
- シーズンが終わると、期待された順位との差で、クラブの評判とファンの数が変わる

## オーナーの評価（フェーズ3-B、数値は `src/game/ownerBalance.ts`）

- 目標：順位（優勝、3位以内、6位以内、10位以内、残留、最下位を避ける）と財務（黒字にする、年俸を予算内に収める、借り入れを減らす）。順位の目標は、評判の順位と戦力の順位の平均で決まる
- 目標の話し合い：開幕までに1回だけ。1段下げると予算が1割減り、1段上げると1割増える
- 信頼度（0〜100、最初は60）：毎月、目標の順位との差、その月の勝ち点、降格圏や最下位かどうか、お金（緊急の借り入れ、オーナーの穴埋め、借り入れの多さ）で上下する
- 1月1日にシーズンを評価する：目標を上回った・達成・あと一歩・届かず・大きく下回った、と財務の目標の達成で信頼度が変わる
- 信頼度が35を下回ると警告、20を下回ると最後の警告。シーズン中に10を下回るか、目標を大きく下回ったうえに40を下回ると解任される
- 信頼度が低いと、予算の増額や借り入れが認められにくくなる

## 監督のキャリア（フェーズ3-C、数値は `src/game/careerBalance.ts`）

| 経歴 | 最初の評判 | 得意 |
| --- | --- | --- |
| 元日本代表 | 70 | 声かけ・面談・チームミーティングの効果が2割大きい |
| 元プロ選手 | 55 | 同じ効果が1割大きい。練習でのケガが1割少ない |
| 指導者の経験あり | 45 | 戦術の熟成が15%早い。練習での成長が5%大きい |
| 経験なし | 30 | 評判の上がり方が3割大きい |

- 難易度：やさしい（オーナーが寛容、最初の年の予算＋10%）、ふつう、むずかしい（オーナーが厳しい、予算−10%）
- どのクラブも選べるが、クラブの評判が監督の評判より15以上高いと、オーナーの最初の信頼度が下がる（最低40）
- 監督の評判は、シーズンの評価で＋6〜−6、優勝で＋6、解任で−5、辞任で−2。無職の間は毎月少し下がる
- AIクラブの監督は、シーズン中に目標より大きく下で降格圏にいるときと、シーズンの終わりに目標より5つ以上下のときに解任されることがある（1シーズンに1〜3人くらい）。2〜3週間で次の監督が決まる
- 在任中のオファーは、シーズンが終わった12月に、今より格上のクラブから届く。受けると1月1日に移る
- 解任や辞任のあとは無職になり、日を進められる（リーグの試合は進む）。監督が空いたクラブからオファーが届き、自分から応募もできる。3か月たってもオファーがなければ、評判の低いクラブから話が来る

## 契約（フェーズ4-A、数値は `src/game/contractBalance.ts`）

- 市場価値：年俸の相場（総合力で決まる）× 年齢の倍率（21歳以下は4年分、25〜27歳は2年分、32歳以上は0.5年分）× 伸びしろ × 契約の残り × 今季の活躍。J1の主力で1億円くらい。他クラブの選手は、知識度に応じた幅で見える
- 代理人：穏やか・ふつう・強気の3つの性格。強気なほど高い年俸を求め、提示できる回数が少ない（3回か2回）。決裂すると14日話せない。契約がまとまると、年俸の3〜8%の手数料がかかる
- 選手の希望：年俸の相場 × 代理人 × 約束する役割（ふさわしい役割より1段下だと15%増し、2段下は断る）× 違約金の高さ × 年数 × クラブの評判と野心 × 忠誠心。出来高ボーナスは、見込み額の7割を年俸と同じように数える
- 更新の交渉：今年で契約が切れる選手と、7月1日〜11月30日。主力とローテーションは自分で交渉し、控えと若手は強化部に任せられる。11月30日までに更新しなかった選手は契約満了
- 12月1日：締め切り。強化部に任せた選手とAIクラブの選手は、序列の低いベテランなら更新しない。選手のほうからも、出場機会や新しい挑戦を求めて断ることがある
- 契約満了の選手：12月に仮の契約をすると1月1日に加入。決まらなければ所属なしになり、3月27日まで獲れる。それでも決まらなければ去る。AIクラブも、足りないポジションや今の2番手より強い選手を獲る
- 新しい契約の年俸は、年俸予算の残りに収まる額まで

## 移籍（フェーズ4-B、数値は `src/game/transferBalance.ts`）

- 移籍期間：冬は1月5日〜3月27日、夏は7月15日〜8月15日。期間の外でも交渉はでき、まとまった移籍は次の移籍期間の初日に成立する
- 売る側の希望の額：市場価値 × 役割の倍率（主力は大クラブ1.6・中1.3・小1.1、ローテーション1.0、控え0.8、若手0.9、移籍リストの選手0.6）。夏に3位以内のクラブは、さらに0.3上でないと売らない。そのポジションの選手が足りなくなる（GKは2人、ほかは理想の人数の半分）なら売らない
- 申し込みの返事は2〜4日後。希望の額以上なら受け、希望の75%以上なら希望の額を返す（2回まで）、それより低ければ断る。合意したら14日以内に選手（代理人）と契約を結ぶ。違約金を払うと、クラブは断れない
- 自分の選手への申し込み：受ける・断る・額を返す（相手が出せる上限は市場価値の1.4倍〜1.05倍、クラブの規模で決まる）を5日以内に決める。返事をしないと断ったことになる。違約金を払われると断れない（選手が残ると決めることはある）
- 移籍金は買う側の移籍予算から出て、売った側には収入として入り、半分がその年の移籍予算に足される
- AIクラブ：移籍期間の決まった日に、足りないポジションか、今の2番手より0.3以上強い選手を、規模に合った年齢と予算の範囲で買う（1年に大3人・中2人・小2人まで）。海外の選手も獲る（外国籍は1クラブ5人まで）。上位18人の平均がリーグ平均より1.5以上強いクラブは、足りないポジションを埋めるだけにする。移籍予算の一部（年俸予算の1割まで）を年俸予算に回せる
- 海外への移籍：6月20日と12月10日に、25歳以下で総合力14以上か、31歳以下で総合力16以上の選手のうち3〜4人に、海外のクラブから話が来る（市場価値の1〜1.5倍。本人が行きたがらなければ消える）。行きたがっている選手の移籍を断ると、モラルが20下がる
- レンタル：23歳以下の控えか若手、またはレンタルのリストに載っている選手で、契約がその年より先まで残っている選手。11月30日まで借り、年俸は全額か半分を借りる側が払う。12月1日、契約の締め切りの前に元のクラブへ戻る

## スカウトと新人（フェーズ4-C、数値は `src/game/scoutingBalance.ts`）

- 知識度：自分のクラブの選手は100%。同じリーグの選手と所属なしの選手は50%、海外の選手と新人の候補は20%から始まる。スカウトで調べると上がり、対戦すると相手の出場した選手が少しずつ分かる（70%まで）。一度上がった知識度は下がらない
- スカウトの人数はクラブの規模で決まる（大3人、中2人、小1人）。1人に1つずつ仕事を頼める
- 選手を指名して調べる：国内と新人の候補は5日、海外は10日。知識度が35上がる
- 条件を付けて探す：地域（国内のリーグ、高校・大学、南米、アジア、ヨーロッパ）、ポジション、年齢を決める。国内と高校・大学は14日、海外は21日で、まだよく知らない選手を良い順に5人まで報告する（知識度が30上がる）。見つけた海外の選手には、移籍金で獲得を申し込める（市場価値の0.9倍が目安、外国籍は5人まで）
- レポート：総合力の幅、伸びしろ（星。知識度が高いほど正確）、市場価値、長所と短所、人柄のほのめかし、勧める度合い（自分のクラブの同じポジションの選手と比べる。知識度40%未満では出さない）
- 新人の候補：6月1日に高校生36人と大学生28人を発表。10月31日まで内定を出せる（約束する役割と年俸。返事待ちは5人まで）。AIクラブも6月〜10月に6回、内定を出す。候補は最初の内定から21日後に、クラブの評判、出番の見込み、役割、年俸を比べて選ぶ。内定を受けた候補は1月10日に3年契約で加入し、足りない分は強化部が新人を獲って埋める。決まらなかった候補は去る

## 公開のしかた

`main` に取り込まれると、GitHub Actions（`.github/workflows/pages.yml`）がゲームを組み立てて GitHub Pages に公開する。
プルリクエストでは、型の確認と自動テストが回る（`.github/workflows/test.yml`）。
版を上げるときは、`package.json` の `version` と `src/ui/about.ts` の `APP_VERSION` を一緒に変える（ずれるとテストが落ちる）。
セーブの形を変えたら、`src/game/world.ts` の `STATE_VERSION` を上げ、`src/game/save.ts` に古い形からの変換を足す（公開したあとは、遊んでいる人のセーブを壊さないため）。

## 開発用のコマンド


## 試合エンジンのしくみ（要点）

- ピッチを縦6×横5の30マスに分け、ボールを持った選手のプレー（パス、ドリブル、シュート、クロス、クリア）を一手ずつ計算する
- 各選手は、フォーメーション、役割、チーム指示から「攻撃時の位置」と「守備時の位置」を持ち、近くのマスに影響を与える
- プレーの成功率は、攻める側の能力と、そのマスで守る側がかけている「圧力」で決まる
- プレスは「相手陣内でボールに寄せる力」として圧力に加わる。前線と中盤の運動量・スピードが高いほど強い
- 守備ラインが高いほど裏へのパスが通りやすく、FWが最終ラインより速いとGKと1対1の抜け出しになる。GKの飛び出しで防げる
- ボールを失った側は、約9秒の間、攻めの形のままで守備が整っていない。攻撃の姿勢と守備ラインが高いチームほど崩れが大きい
- カウンター：テンポが速く長いボールを使うチームは、相手が崩れている間に縦へ速く攻め、裏へ抜け出しやすい。守備的でも前線の選手はゴール前に残る
- 引いて守る相手（攻撃の姿勢と守備ラインが低い）には、短いパスでつなぐチームほどペナルティエリアに入りにくい
- 長いボールは相手のプレスを外しやすく、寄せられても奪われにくいが、パスの精度は落ちる
- 23項目の能力値はすべて試合のどこかで効く（`test/attributes.test.ts` で確かめている）
- スタミナは時間とともに減り、能力値が下がる。65まではゆるやかに、65を切ると急に下がるので、終盤は交代が効く。プレスやテンポを上げると早く減る。試合開始時のスタミナはコンディションで決まる
- 蓄積疲労、モラル、戦術の熟成度、声かけがその日の出来に響く。試合中のケガは、タックル、ファウル、接触のない場面で起きる
- AIの監督は、60・70・80分に疲れた選手を交代し、負けていれば攻撃的に、勝っていれば守備的に切り替える。ケガ人が出たら、前半でもすぐに交代する
- 試合の計算では、能力値の平均（12）からの差を0.8倍に縮めて使い、番狂わせが起きる余地を残している
- 試合の出来事（ゴール、シュート、カード、ケガなど）は、関わった選手、ピッチ上の位置（どのマスからどのマスへ）、xGを持つ

結果の分布を変えたいときは、まず `src/engine/config.ts` の数値を変えて、`npm run simulate` で確かめる。
